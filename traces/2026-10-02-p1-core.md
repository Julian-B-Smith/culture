# p1-core — C++ core bit-exact with the JS reference

- **Queue item:** ROADMAP P1 (headless core, bit-exact)
- **Why:** Port `reference/core.js` to a pure C++20 `libculture` with a trace CLI, proved against the goldens, as the base for the native viewer (P2) and sound (P3).
- **Evidence consulted:** reference/core.js (normative); docs/handoff/SPEC.md §1–§3, §8, §9; PORT_PLAN P1; tools/golden.js and compare.js; critic review (rung-2, Opus, 24 extra JS-vs-C++ configurations); node 24.10 / V8 13.6 symbol table.
- **What changed:** `core/` (port + vendored explicit-fma fdlibm), `trace/` (traces, `--bench`, `--deep`), `tests/` (vectors, trig, deep tracer, flavor probe), `CMakeLists.txt`, five new `./verify` gates, CI builds the C++ with GCC on Linux. Decisions D-025…D-028; lessons L0002–L0004.
- **Results:**
  - All four goldens PASS with `--float-rel 0` (record/lastMax equal to all 10 printed digits), births footers included.
  - Deep hidden state bit-identical every generation on all four golden runs and two chaos runs (sliced search, forceEmerge, 37×23, extinctions).
  - 36 unit vectors bit-identical; fdlibm trig = node's V8 on 2.24M values.
  - Bench, 440×280, Release, Apple Silicon, mean `step()` over 4,000 steps after 50 warm-up, search excluded: seed 1 1.995 ms (p99 2.577, max 5.475), seed 2 2.127 ms (p99 3.972, max 12.568), seed 3 2.157 ms (p99 2.617, max 60.774). Budget 4 ms on the mean (criterion 2); tails carried to P2.
- **Alternatives rejected:** SIMD (not needed once the neighbor-scan skip landed); std::cos/sin with a recorded difference, and plain fdlibm (D-027); adding deep hashes to the pinned golden format (D-025).
- **Verify:** `./verify full` exit 0 before commit (hash in .harness/last-verify.json). Gates proven to fire by plants: `0.8f` in pressure decay → cpp_deep red while all goldens stayed green; float-only `res*forget` → caught only by stress-seed-4 under the old gates, now by cpp_deep; one unfused fdlibm term → cpp_trig red; empty JS deep trace → line-count failure.
- **Open questions:** first Linux/GCC/glibc CI run is the evidence for parity on that toolchain (std::fma in software on non-FMA x86 is correctly rounded, so the pinned trig hash should hold — unverified until CI runs).
